
# Feature Engineering

## 1. Overview

Feature engineering prepares the preprocessed Diabetes 130-US Hospitals for Years 1999–2008 dataset for machine learning.

The objective is to convert the patient and hospital encounter characteristics into numerical representations that can be used by Logistic Regression and Random Forest to predict readmission within 30 days of discharge.

The same feature engineering process is applied to both models to support a fair comparison.

## 2. Notebook Used

Feature engineering is implemented in:

`FeatureEngineering.ipynb`

The notebook is located in the source folder in root of the repository.

It loads the training and testing datasets generated by the preprocessing stage and applies numerical imputation, categorical imputation, one-hot encoding and numerical scaling.

## 3. Feature Engineering Techniques

### 3.1 Numerical feature identification

Numerical columns are identified using their data types.

These columns include numerical patient and hospital encounter characteristics, such as age and number of previous inpatient visits.

### 3.2 Categorical feature identification

Categorical columns are identified using their data types.

These include patient demographics, diagnoses, medications and the descriptive hospital admission fields created during preprocessing:

- `admission_type`
- `discharge_disposition`
- `admission_source`

The descriptive ID mappings are treated as categorical variables rather than continuous numerical measurements.

### 3.3 Missing-value imputation

Missing numerical values are replaced using the median of each feature calculated from the training data.

Missing categorical values are replaced using the most frequent category in the training data.

The fitted imputers are then applied to the test data without recalculating the imputation values.

### 3.4 One-hot encoding

Categorical features are transformed into binary indicator variables using `OneHotEncoder`.

This allows machine learning models to use categorical information without incorrectly assigning numerical ordering to categories.

The encoder uses `handle_unknown="ignore"` so that categories not observed during training do not cause errors during testing or inference.

### 3.5 Numerical scaling

Numerical features are standardised using `StandardScaler`.

Scaling is included to support Logistic Regression, which can be affected by differences in numerical feature scales.

The scaler is fitted on the training data and then applied to the test data using the same fitted parameters.

## 4. Data Leakage Prevention

The feature engineering transformer is fitted using only the training data.

The test data is transformed using the fitted transformer without learning new imputation values, scaling parameters or categorical encodings.

This prevents information from the test dataset from influencing the feature engineering process.

The training and testing datasets are created using patient-grouped splitting during preprocessing to reduce leakage caused by repeated encounters for the same patient.

## 5. Python Notebook and How to Run

The feature engineering notebook is:

`FeatureEngineering.ipynb`

The notebook requires the following files:

- `outputs/X_train.csv`
- `outputs/X_test.csv`
- `outputs/y_train.csv`
- `outputs/y_test.csv`

These files are created by `src/preprocessing.py`.

From the root of the repository, start Jupyter Notebook:

```bash
jupyter notebook
```

Open `FeatureEngineering.ipynb` and run all cells in order.

The notebook uses the root-level `data`, `outputs` and `models` directories.

## 6. Output Files

The notebook saves the following files:

| File | Purpose |
|---|---|
| `models/feature_preprocessor.joblib` | Fitted feature engineering transformer. |
| `outputs/X_train_processed.joblib` | Transformed training features. |
| `outputs/X_test_processed.joblib` | Transformed testing features. |
| `outputs/y_train_processed.joblib` | Training target labels. |
| `outputs/y_test_processed.joblib` | Testing target labels. |
| `outputs/feature_names.csv` | Names of the engineered features. |

These files are used by the two model training notebooks.

## 7. Limitations

One-hot encoding can increase the number of feature columns, particularly for variables with many categories.

The dataset contains historical US hospital records from 1999 to 2008, and the resulting features may not fully represent current South African hospital settings.

The engineered features support prediction of recorded readmission within 30 days and should not be interpreted as proof of avoidable readmission or causation.
